# v3.0.7 🦕 Iguanodon — secret text hidden by default, no clipboard reads

Three privacy fixes in the main app, building on [v3.0.6](v3.0.6.md). The
cryptography, container format, wordlist, and self-tests are untouched, and
the Recovery tool is byte-identical to v3.0.6 (its label stays
**IttyBitz Recovery v3.0.6**). `npm run test:crypto` still passes every
historical fixture in both directions.

## Fixes

- **Secret text is blurred the moment it has content.** The Encrypt Text
  field used to show what you typed until you clicked the eye to hide it.
  Now the first character typed or pasted is already blurred; click the eye
  to reveal your typing, and the field hides itself again whenever it is
  emptied or the mode changes, so every new secret starts hidden.
- **The app never reads the clipboard.** Sixty seconds after a copy, the
  clipboard auto-clear used to read the clipboard to check it still held
  what the app had written. Browsers gate clipboard reads behind a
  permission prompt, so a minute after copying a password or result the
  browser asked whether the page could see the clipboard, with no visible
  cause. Auto-clear now works without reading: if the page stayed focused
  and nothing else was copied from it since the write, the clipboard can
  only still hold what the app put there, so it is overwritten. If you left
  the page or copied something else, it is left alone. The status message
  and README say so.
- **The seed fingerprint is cleared when the secret is.** After encrypting a
  seed phrase as text, the secret field was cleared but the master
  fingerprint stayed on screen. It now disappears at the same moment. On the
  decrypt side it still appears beside the blurred result, which is its
  purpose there: confirming the right seed without revealing it.

## For users

Nothing to do. Existing `.ibitz` files and encrypted text decrypt exactly as
before. If your browser was asking for clipboard permission after a copy,
that stops with this release.
